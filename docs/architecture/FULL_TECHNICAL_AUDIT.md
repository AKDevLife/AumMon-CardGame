## 0. Critical framing finding — what "EDO Battle" actually is

The mission brief calls the existing game "AumMon Original". The repository's **current and only** game is the **Casual Discard Edition** (2–8 players, shedding-style card game, `ruleset_version = "13"`), not the original 1v1 TCG.

- The 1v1 TCG (rulesets `"1"`–`"6"`, characters, HP, decks) was **removed** in task 12.4 and its tables/data were dropped by `supabase/migrations/20261122000100_discard_cutover.sql` (`drop table … characters, card_definitions, deck_templates, deck_template_cards`; `delete from public.matches`).
- Spec header: `aummon_game_spec.md` line 3 — "Replaces the retired 1v1 TCG (rulesets 1–6)".
- Theme is "Everyday Objects" (spec §1), which matches the new name **EDO (Every Day Object) Battle**.

**Conclusion:** "EDO Battle" = Casual Discard Edition (engine `packages/game-engine/src/discard/`). There is no older playable game to preserve. This audit and all plans assume that mapping. **Owner confirmation requested** (see GAME_MIGRATION_PLAN §1).

## 4. Technical debt

1. **No game identifier.** `ruleset_version` is the only discriminator; it is hard-coded as `'13'` in at least `lobby.ts` (create + join), `game.ts` (`lockGame`, `GameResponse.rulesetVersion: "13"`, `startMatch`) and in DB CHECK constraints (`20261122000900_ruleset13_glue.sql`). Adding a second game requires a real `game_id`.
2. **Single engine namespace export.** `packages/game-engine/src/index.ts` exports `discard`; server imports it directly. No game registry/dispatch.
3. **Request-driven bots/timers.** If no client polls, bots and timeouts do not advance. Acceptable for EDO; risky for Poker (timed betting) and for all-bot-turn chains if a client disconnects.
4. **Realtime is "ping then refetch".** Every match row update triggers each client to call `game-view` (which itself can advance bots). Fine at playtest scale; N players × updates cost grows with more games.
5. **Per-seat N+1 updates** in `saveGame` (`for (const s of locked.seats) update …`).
6. **Large components:** `GamePage.tsx` 819 lines, `AdminPage.tsx` 664 lines.
7. **Generated engine copy** for Deno (`sync-engine.mjs`) — must remain in deploy procedure; multi-engine needs the same sync.
8. **Integer seat model 1–8** in DB CHECKs; Poker 9/10-max would need widening.
